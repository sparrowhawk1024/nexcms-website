WHAT THIS CONTENT TYPE IS FOR:
  The "Deals of the Day" section on the homepage and the /deals page.
  One entry = one deal (one product at a special price for a limited time).
  Each deal card shows a live countdown timer and a "Grab Deal →" button.

HOW TO ADD THE REFERENCE FIELD:
  When adding the 'product' field, select type = "Reference".
  In the reference settings, choose "Single" and select the 'product' content type.
  This creates a dropdown in the deal entry where you can search and pick a product.

────────────────────────────────────────────────────────────────────────────────
HOW TO FILL IN A DEAL ENTRY (Example):
────────────────────────────────────────────────────────────────────────────────

  title       → "Deal of the Day"
  product     → [search and select] "Samsung Galaxy S25 Ultra 5G"
  deal_price  → 109999          (cheaper than the product's price of 129999)
  ends_at     → 2025-06-01 23:59  (the deal expires at midnight June 1st)
  active      → true

  NOTE: The discount % is calculated automatically:
        ((129999 - 109999) / 129999) × 100 = 15.4% → shows as "15% OFF"

────────────────────────────────────────────────────────────────────────────────
TIPS FOR MANAGING DEALS:
────────────────────────────────────────────────────────────────────────────────

  - Run 2-4 deals at a time. Too many loses urgency.
  - Always set ends_at to create scarcity (countdown timer motivates action).
  - When a deal expires, set active = false. The timer will show "Deal expired"
    until you do this.
  - The deal_price MUST be less than the product's regular price to show
    a meaningful discount badge.
  - You can run the same product as a deal multiple times — just create new
    deal entries with new dates.
  - Schedule deals by creating entries in advance with future ends_at dates
    and setting active = true only when you want them to go live.

DEPLOYMENT EXTENSION: CONTENTSTACK WEBHOOK → NEXSTORE AUTO-REVALIDATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHAT THIS IS:
  NexStore uses Next.js "Incremental Static Regeneration" (ISR).
  Pages are pre-built and served from cache for speed. By default they
  refresh every 60 seconds. With the webhook extension, every time you
  PUBLISH an entry in Contentstack, NexStore instantly clears the cache
  for the right pages — no waiting, no manual deploys.

  Contentstack → (entry published) → webhook POST → /api/revalidate → Next.js
  cache cleared instantly → your live site shows new content within seconds.

────────────────────────────────────────────────────────────────────────────────
STEP 1: GENERATE A WEBHOOK SECRET
────────────────────────────────────────────────────────────────────────────────

  This secret prevents random people from clearing your site's cache.
  Generate a strong random string. Options:

  Method A (terminal):
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

  Method B (online):
    Visit https://generate-secret.vercel.app/32 and copy the result.

  Example value:  a3f8e2c1d4b7a9f0e3c6b8a1d4f7e2c5a8b1d4e7f0a3c6b9d2e5f8

  KEEP THIS SECRET PRIVATE. Never commit it to git.

────────────────────────────────────────────────────────────────────────────────
STEP 2: ADD THE SECRET TO YOUR ENVIRONMENT
────────────────────────────────────────────────────────────────────────────────

  A) Local development (.env.local):
     Open .env.local and add:
       CONTENTSTACK_WEBHOOK_SECRET=<your secret here>

  B) Vercel (production):
     Project Settings → Environment Variables → Add:
       Name:  CONTENTSTACK_WEBHOOK_SECRET
       Value: <your secret here>
       Environments: Production, Preview

  C) Netlify (production):
     Site Settings → Build & Deploy → Environment → Add variable:
       Key:   CONTENTSTACK_WEBHOOK_SECRET
       Value: <your secret here>

────────────────────────────────────────────────────────────────────────────────
STEP 3: CONFIGURE THE WEBHOOK IN CONTENTSTACK
────────────────────────────────────────────────────────────────────────────────

  1. Log in to Contentstack → open your NexStore stack.
  2. Go to: Settings → Webhooks → + New Webhook

  Fill in the form:
  ┌─────────────────────┬─────────────────────────────────────────────────────┐
  │ Field               │ Value                                               │
  ├─────────────────────┼─────────────────────────────────────────────────────┤
  │ Webhook Name        │ NexStore ISR Revalidation                           │
  │ URL                 │ https://your-domain.com/api/revalidate              │
  │ Method              │ POST                                                │
  │ Custom Header Name  │ x-webhook-secret                                    │
  │ Custom Header Value │ <your secret from Step 1>                           │
  └─────────────────────┴─────────────────────────────────────────────────────┘

  Replace "your-domain.com" with:
    - your Vercel URL:  nexstore-xyz.vercel.app
    - your custom domain: nexstore.in

  3. Under "Triggers", check these events:
       ✅ Entry → Published
       ✅ Entry → Unpublished
       ✅ Entry → Deleted

  4. Leave "Retry" enabled (3 retries recommended).

  5. Click Save.

────────────────────────────────────────────────────────────────────────────────

  A) Health check (no secret needed):

     In the Contentstack response panel, you should see HTTP 200.

  C) Test from terminal (PowerShell):

       -Headers @{"x-webhook-secret"="<your-secret>"} `

ADDENDUM: COOKIES, CONSENT & PERSONALIZATION ENGINE (localStorage-based)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This section details the client-side cookie consent compliance banner and the
privacy-compliant personalization engine. All user choices, recently viewed history,
and preferences are saved directly on the client (localStorage), requiring zero database
storage and complying with global privacy requirements.

────────────────────────────────────────────────────────────────────────────────
1. COOKIE CONSENT ENGINE (HOW IT WORKS)
────────────────────────────────────────────────────────────────────────────────

The store features a premium, cyberpunk-styled floating Cookie Consent Banner.
Cookies are divided into three categories:

  Category            | Key        | Purpose
  ────────────────────┼────────────┼────────────────────────────────────────────
  Essential           | essential  | Always enabled. Powers cart, checkout, session.
  Analytics           | analytics  | Optional. Controls tracking page-view counts.
  Personalization     | marketing  | Optional. Controls recommendation rows & fav category highlights.

Consent Rules:
  - If a user rejects optional cookies, they are still shown the "Recently Viewed"
    row (as it is considered basic user-experience utility), but the title is plain.
  - If a user rejects personalization, the "Picked For You" recommendation section
    is completely hidden, and category active glows are disabled.
  - Analytics (page views) are only tracked if "analytics" is explicitly accepted.

────────────────────────────────────────────────────────────────────────────────
2. PERSONALIZATION ENGINE (HOW IT WORKS)
────────────────────────────────────────────────────────────────────────────────

A personalization context monitors user interactions:
  - Product Views: Visiting a product detail page logs a snapshot of the product details
    (last 12 products are stored in "nexstore_recently_viewed" in localStorage).
  - Category Visit Count: Visits are tallied by category. The category with the
    highest view count is dynamically computed as the "topCategory".
  - Category Clicks: Clicks on categories from the home grid are tracked.
  - Picked For You: Recommends 5 items in the user's "topCategory" that they haven't
    already viewed, sorted by highest rating first. Only displays if they have viewed
    at least 2 products and personalization (marketing) cookies are accepted.

  ─────────────────┼────────┼───────────────────────────────────────────────────
