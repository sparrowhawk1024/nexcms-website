WHAT THIS CONTENT TYPE IS FOR:
  The "Deals of the Day" section on the homepage and the /deals page.
  One entry = one deal (one product at a special price for a limited time).
  Each deal card shows a live countdown timer and a "Grab Deal →" button.

HOW TO ADD THE REFERENCE FIELD:
  When adding the 'product' field, select type = "Reference".
  In the reference settings, choose "Single" and select the 'product' content type.
  This creates a dropdown in the deal entry where you can search and pick a product.

────────────────────────────────────────────────────────────────────────────────
HOW TO FILL IN A DEAL ENTRY (Example):
────────────────────────────────────────────────────────────────────────────────

  title       → "Deal of the Day"
  product     → [search and select] "Samsung Galaxy S25 Ultra 5G"
  deal_price  → 109999          (cheaper than the product's price of 129999)
  ends_at     → 2025-06-01 23:59  (the deal expires at midnight June 1st)
  active      → true

  NOTE: The discount % is calculated automatically:
        ((129999 - 109999) / 129999) × 100 = 15.4% → shows as "15% OFF"

────────────────────────────────────────────────────────────────────────────────
TIPS FOR MANAGING DEALS:
────────────────────────────────────────────────────────────────────────────────

  - Run 2-4 deals at a time. Too many loses urgency.
  - Always set ends_at to create scarcity (countdown timer motivates action).
  - When a deal expires, set active = false. The timer will show "Deal expired"
    until you do this.
  - The deal_price MUST be less than the product's regular price to show
    a meaningful discount badge.
  - You can run the same product as a deal multiple times — just create new
    deal entries with new dates.
  - Schedule deals by creating entries in advance with future ends_at dates
    and setting active = true only when you want them to go live.

    "Mobiles" (capital M) and "mobiles" (lowercase m) are NOT the same.
    Use lowercase everywhere to be safe.

STEP-BY-STEP SETUP ORDER (do this in order — don't skip steps)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  STEP 1: Open 'product' content type and add the 9 new fields listed above.
  STEP 2: Open each existing product entry and fill in the new fields:
            - rating (e.g. 4.2)
            - review_count (e.g. 150)
            - brand (e.g. "Samsung")
            - delivery_days (e.g. 2)
            - is_best_seller → tick for your top 5-10 products
            - is_new_arrival → tick for your newest products
          Save and publish each entry.
  STEP 3: Create the 'category_page' content type with the 7 fields.
          Create entries for each category (Mobiles, Laptops, etc.).
          Publish all entries.
  STEP 4: Create the 'banner' content type with the 9 fields.
          Create 2-3 banner entries with images. Set active = true.
          Publish all entries.
  STEP 5: Create the 'deal' content type with the 5 fields.
          Create 1-4 deal entries referencing your products.
          Set ends_at to a future date. Set active = true.
          Publish all entries.
  STEP 6: Create the 'review' content type with the 8 fields.
          Create 3-5 reviews for each product you want reviews on.
          Make sure product_uid matches exactly.
          Publish all entries.
  STEP 7: Open your website at http://localhost:3000 (or your live URL).
          Check each section appears correctly.

  PUBLISHING REMINDER: In Contentstack, entries must be PUBLISHED (not just saved)
  to appear on the website. Look for the green "Publish" button in each entry.

TROUBLESHOOTING — IF SOMETHING DOESN'T APPEAR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PROBLEM: I added a banner but the homepage still shows the animated fallback.
  FIX:     Make sure the banner entry is PUBLISHED (not just saved).
           Make sure the 'active' field is set to true.
           Wait 60 seconds and refresh (data is cached for 60 seconds).

  PROBLEM: I set is_best_seller = true but the product doesn't appear.
  FIX:     Make sure you PUBLISHED the product entry after editing.
           The 'is_best_seller' field must exist in the content type first.
           Check the field UID is exactly "is_best_seller" (with underscore).

  PROBLEM: Reviews are not showing on the product page.
  FIX:     Check that the product_uid in the review entry EXACTLY matches
           the entry UID of the product (starts with "blt...").
           Make sure the review entry is PUBLISHED.
           Make sure the 'review' content type UID is exactly "review".

  PROBLEM: The deal countdown shows "Deal expired" but the date is in the future.
  FIX:     Check that the ends_at field is a Date/Time type (not just Date).
           Make sure you set a time along with the date (not just midnight).
           The time zone matters — Contentstack uses UTC by default.

  PROBLEM: Category filter not working (clicking "Mobiles" shows all products).
  FIX:     The 'category' field on your product entries must EXACTLY match
           the 'slug' field on your category_page entries.
           Example: product.category = "mobiles" and category_page.slug = "mobiles"
           Both must be the same — including case (use all lowercase).

  PROBLEM: The site takes a long time to show updated content.
  FIX:     The website caches data for 60 seconds. Wait 60 seconds and refresh.
           To make it faster, change "export const revalidate = 60" to
           "export const revalidate = 10" in the page files.
