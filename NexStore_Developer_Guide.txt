FILE 1:  contexts/CartContext.tsx
PURPOSE: Shopping cart state management
────────────────────────────────────────────────────────────────────────────────

WHAT IT DOES:
  This file creates a "global shopping cart" that any component on the website
  can access. It works like a mini-database that lives in the user's browser
  memory while they shop.

  It stores:
  - A list of cart items (product + quantity)
  - The total number of items in the cart
  - The total price of all items
  - Whether the cart drawer (side panel) is open or closed

  It provides these actions:
  - addToCart(product)      → adds a product; if it's already in the cart,
                               increases its quantity by 1
  - removeFromCart(uid)     → completely removes a product from the cart
  - updateQuantity(uid, n)  → changes the quantity; if n=0, removes the item
  - clearCart()             → empties the entire cart
  - setIsOpen(true/false)   → opens or closes the cart side panel

HOW IT WORKS (CartProvider):
  The CartProvider component wraps the entire website (see app/layout.tsx).
  Any component inside it can call useCart() to get all the cart functions.

HOW IT WORKS (useCart hook):
  Any component that needs cart data imports useCart() like this:
    const { addToCart, totalItems } = useCart();

SECTION 4: CONTENTSTACK SETUP GUIDE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

To unlock each feature, do the following in your Contentstack dashboard:

────────────────────────────────────────────────────────────────────────────────
STEP 1: Add new fields to the EXISTING 'product' content type
────────────────────────────────────────────────────────────────────────────────

Go to: Content Models → product → Edit

Add these fields one by one:

  Field Label        | UID             | Type     | Note
  ─────────────────────────────────────────────────────────
  Rating             | rating          | Number   | Values: 1.0 to 5.0
  Review Count       | review_count    | Number   | Total number of reviews
  Is Best Seller     | is_best_seller  | Boolean  | Enables /best-sellers
  Is Featured        | is_featured     | Boolean  | For featured sections
  Is New Arrival     | is_new_arrival  | Boolean  | Enables /new-arrivals
  Sale Ends At       | sale_ends_at    | Date     | Enables countdown timer
  Brand              | brand           | Text     | e.g., Samsung, Apple
  Delivery Days      | delivery_days   | Number   | e.g., 2
  Sponsored          | sponsored       | Boolean  | Shows "Ad" label

After adding, go to each product entry you want to affect and fill in the fields.

────────────────────────────────────────────────────────────────────────────────
STEP 2: Create the 'review' content type (for customer reviews)
────────────────────────────────────────────────────────────────────────────────

Go to: Content Models → + New Content Type
  Name: Review
  UID:  review

Add these fields:
  title            | Short text  | Required
  product_uid      | Short text  | Put the product's UID here (copy from product entry URL)
  reviewer_name    | Short text  | Required
  rating           | Number      | 1 to 5
  review_body      | Rich text   | The full review text
  verified_purchase| Boolean     | Shows green "Verified Purchase" badge
  helpful_count    | Number      | Number of helpful votes
  published_date   | Date        | When the review was written

To add a review: Create a new 'review' entry, set product_uid to the exact
UID of the product (visible in the URL when editing the product entry).

────────────────────────────────────────────────────────────────────────────────
STEP 3: Create the 'banner' content type (for the hero carousel)
────────────────────────────────────────────────────────────────────────────────

Go to: Content Models → + New Content Type
  Name: Banner
  UID:  banner

Add these fields:
  title           | Short text  | Required
  subtitle        | Short text  |
  desktop_image   | File        | Upload a banner image (1920×500 px recommended)
  mobile_image    | File        | Upload a mobile version (optional)
  cta_label       | Short text  | Button text, e.g., "Shop Now"
  cta_url         | Short text  | Button link, e.g., "/deals"
  badge_text      | Short text  | e.g., "Up to 60% Off"
  active          | Boolean     | Must be true to show the banner
  sort_order      | Number      | Lower number = shows first

Create 1–3 banner entries, set active = true, and they'll replace the
animated fallback banners on the homepage.

────────────────────────────────────────────────────────────────────────────────
STEP 4: Create the 'deal' content type (for Deals of the Day)
────────────────────────────────────────────────────────────────────────────────

Go to: Content Models → + New Content Type
  Name: Deal
  UID:  deal

Add these fields:
  title           | Short text  | e.g., "Deal of the Day"
  product         | Reference   | Reference type → select 'product' content type
  deal_price      | Number      | The discounted price
  ends_at         | Date/Time   | When the deal expires (countdown timer uses this)
  active          | Boolean     | Must be true to show the deal

Create a deal entry, link it to a product, set a deal_price lower than
the product price, set ends_at to a future date/time, set active = true.

────────────────────────────────────────────────────────────────────────────────
STEP 5: Create the 'category_page' content type (for the category grid)
────────────────────────────────────────────────────────────────────────────────

Go to: Content Models → + New Content Type
  Name: Category Page
  UID:  category_page

Add these fields:
  title           | Short text  | e.g., "Mobiles"
  slug            | Short text  | URL-safe text, e.g., "mobiles"
  icon            | Short text  | An emoji, e.g., "📱"
  banner_image    | File        | Category banner image (optional)
  description     | Short text  | Short description
  sort_order      | Number      | Display order
  active          | Boolean     | Must be true to show the category

Create entries for: Mobiles, Laptops, Headphones, Speakers
Set active = true for each one. They'll replace the fallback categories.

SECTION 6: HOW THE DATA FLOWS (END TO END)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  You update data in Contentstack
          ↓
  Contentstack stores it in their cloud
          ↓
  Next.js server fetches it via lib/contentstack.ts
  (fetches are cached for 60 seconds — see "revalidate = 60")
          ↓
  Data is passed as props to page components (app/page.tsx, etc.)
          ↓
  Page components pass data to UI components (ProductCard, DealCard, etc.)
          ↓
  User sees the updated content on the website

To make changes appear faster: Change "export const revalidate = 60" to
"export const revalidate = 10" (10 seconds) or "0" (always fresh, slower).

To make changes appear instantly: Use Contentstack Webhooks to trigger
Next.js cache revalidation via the /api/revalidate route (advanced feature).
